# ADR-002 混合 Feed 归并与分页状态机

状态：已采纳，待实现与验收。基线：SDD V2.1 §4 和 §10。API 统一使用 pageState。

## 修正协议

只限制上一页最后返回项无法让空页推进。各来源独立预取并提前推进边界，也可能跳过有效候选。采用全局归并消费边界，另保存返回边界用于表达 API 契约。

- `globalBoundary` 是最后返回的 (time,id)，初始为空。下一页所有来源严格小于该边界。
- `consumedBoundary` 是最后完全处理的全局候选，包括被过滤的候选。下一次扫描取它和 globalBoundary 的较小值。首屏另限制 published_at_ms ≤ snapshotTime。
- `sourcePositions` 为各来源真正消费的位置，`pendingCandidates` 为请求内预取缓冲。只推进已处理的来源位置；翻页丢弃预取缓冲，并以已消费位置重读。默认游标仅携带足以重建各来源安全边界的共享 consumedBoundary，各来源位置在新请求按该边界初始化。无需保存累计 ID 集。
- 各路必须有已排序的队首或已确认耗尽，才可消费最大候选。若某路查询超时或在确定队首前预算耗尽，不越过该路未知区间。不同来源的同一帖子以同一个不可变元组排序；一次归并消费所有相等队首，再做权威状态和关注代次检查。批量校验可预取，但不得提交未处理的位置。
- SQL 使用 `published_at_ms < :ts OR (published_at_ms = :ts AND id < :id)`，并按该二元组 DESC 取有界批次。Redis 见 ADR-001。SQL 及 Redis 的来源必须使用相同上界。

## API 与故障

响应为 items、nextCursor、pageState、scanned。HAS_MORE 表示已知还有候选；UNKNOWN 表示预算结束尚不能判断；EXHAUSTED 表示本次所有来源耗尽。前两者必须有游标，EXHAUSTED 的游标为 null。空页 UNKNOWN 必须至少消费一个全局候选；预算配置须允许初始化所有逻辑来源并完成一次消费。来源不可用或无法推进时返回可重试错误，保留原游标，或经同一边界切换到完整的权威来源。

游标签名绑定版本、用户、查询参数、snapshotTime、两种边界、关注图版本和过期时间。无效令牌拒绝；关注图变化返回 CURSOR_STALE。迁移或索引恢复若无法证明同一边界上的覆盖，则同样要求刷新。默认无状态，令牌大小与作者数无关；未来物化快照可用短 TTL 服务端会话，需计入存储、过期和失败重启成本。

迟到候选若已落在消费边界之前，留待刷新首页。位于边界之后的迟到候选仍可按序出现。L1 对固定候选集保证完整遍历，对变化中的集合遵守此可见性边界。

## 验收

T02–T03、T13–T15。重点覆盖缓冲中仍有有效项时翻页、迟到新帖进入另一来源、连续空页推进、来源超时不冒充耗尽，以及固定数据集与 SQL 全量顺序逐项对照。

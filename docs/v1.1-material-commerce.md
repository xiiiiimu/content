# v1.1 素材限量抢购

基线：`origin/main` @ PR #14 merge (`0426597`)。功能分支：`feat/v1.1-material-commerce`。

## 范围

1. **限量抢购**：活动配置、站内链接、Redis Lua 原子预扣、RocketMQ 异步落单、订单查询、PURCHASE 下载权益。
2. **退款 / 黑名单 / 抽奖资格**：中奖后用户申请退款、买家申请与强制退款、商家拉黑、同账号素材串行决策、启用 `PURCHASE` 资格工具。

2026-11-18 规则更新以 [追加 PRD](material-commerce-addendum.md) 和 [实施契约](commerce-ingress-v2.md) 为准。关注、预览和分享权限不再决定登录用户能否购买；下架与有效下载权益仍由 MySQL 最终授权。

支付与退款均为模拟内部状态机，不接入任何支付渠道，详见下文 [支付与退款边界](#支付与退款边界模拟实现)。

## 核心表（V17）

| 表 | 作用 |
|---|---|
| `material_sale_campaigns` | 库存上限 / 已售 / 窗口；`open_guard` 保证同帖仅一个 OPEN |
| `material_purchase_requests` | 预占请求终态 PROCESSING→SUCCEEDED/REJECTED |
| `material_orders` | `UNIQUE(user_id, post_id)`；PAID / REFUNDED |
| `material_refund_requests` | 退款申请；成功 guard 每单一成功 |
| `merchant_blacklist` | 商家维度拉黑 |
| `account_material_decision_locks` | 购买落单与发奖串行 |
| `material_sale_consume_receipts` | 消费去重回执 |

## 路径

1. 买家抢购 → Lua 预扣并 XADD → 立即返回 Redis PROCESSING → Stream 可靠桥接 → MySQL 请求及待发记录同事务提交 → RocketMQ `PurchaseSettle`
2. 消费者 MySQL 条件更新库存、建单、发 PURCHASE 权益后 ACK
3. 中奖发奖前锁 `(account, post)`；保留 PAID 订单与新中奖权益，通知用户可申请中奖退款。审批成功使用 GIVEAWAY_REFUND，原订单仍计入 PURCHASE 资格。

## 配置

- `content.sale.enabled`（默认随 media）
- `content.sale.scan-enabled=true`：运行真实 Stream 桥接和持久化待发送扫描；生产同时启用 producer/consumer。旧 sync-settle 参数保留配置兼容，入口始终立即返回 PROCESSING；领域回归显式泵送和结算，不能当作真实 MQ 证据。
- `content.sale.topic` / `content.sale.consumer-enabled` / `content.sale.namesrv`

## 支付与退款边界（模拟实现）

本期**没有接入真实支付或退款渠道**，不发生任何资金流动，也不调用外部支付服务。以下状态流转全部由系统内部直接写入：

| 环节 | 当前（模拟）实现 | 真实支付下应有的样子 |
|---|---|---|
| 价格 | `price_cents` 由作者配置，只用于展示和记账 | 金额、币种以支付单为准，下单时冻结 |
| 下单 / 付款 | 预占成功后经 MQ 落单，`material_orders` 直接插入 `PAID`，`paid_at_ms` 取落单时间 | 先建待支付单（如 `PENDING_PAYMENT`），收到并验证渠道回调后才置 `PAID`；超时未付则释放预占 |
| 付款结果 | 落单成功即视为（模拟）付款成功，前端据此显示订单与下载入口 | 以渠道回调和主动查单结果为准 |
| 买家退款 | 申请 → 商家批准 → `PAID → REFUNDED`，撤销购买权益、归还一次名额 | 批准后向渠道发起退款，`REFUND_PENDING` → 渠道结果回调 → `REFUNDED` / `REFUND_FAILED` |
| 中奖退款 | 同上，原因 `GIVEAWAY_REFUND`，保留中奖权益 | 同上 |
| 强制退款 | 有权限的模拟运营操作，直接 `PAID → REFUNDED`（`BUYER_FORCED`） | 同上，另需审批和审计 |

接入真实支付前至少要补：

1. **回调验签**：校验渠道签名和证书、时间戳与防重放；核对金额、币种、商户号、订单号与本地支付单一致；回调接口与内部接口隔离。
2. **幂等**：渠道交易号、退款单号唯一约束；重复回调只确认一次；向渠道发起退款时带幂等号，网络超时后先查单再重试；本地“每单至多一次成功退款”的约束保留。
3. **状态机**：新增待支付、支付失败 / 关闭、退款中、退款失败等状态；预占在支付超时后释放；落单与权益发放只在确认付款后进行。
4. **对账**：每日拉取渠道账单，与 `material_orders`、`material_refund_requests` 逐笔核对（单边账、金额不符、状态不符），差异进入人工处理队列；保留对账记录。
5. **其他**：密钥与证书的保管和轮换；退款原路返回；部分退款当前不支持；支付数据的合规评估。

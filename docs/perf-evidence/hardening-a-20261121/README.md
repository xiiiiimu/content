## 3. 登录前后对比（A2 登录限流 + A4 BCrypt 有界线程池）

`infra/perf/auth/login-phase.sh`：独立库，预置 7000 个账号（复制同一个 BCrypt 哈希，cost 10），每次迭代用不同账号、正确密码；开放模型，warmup 10 rps 10 s，之后 50/100/200 rps 各 30 s，档间休息 65 s；k6 最多 400 VU；同一台 16 逻辑核机器同时运行 k6 与 MySQL/Redis。所有请求来自 127.0.0.1。

| 阶段 | 档 | 实际 rps | 200 | 429 | 5xx | 丢弃 | p50 / p95 / p99 ms | 进程 CPU 均值 / 峰值 |
|---|---|---|---|---|---|---|---|---|
| 改前 `3610fa7` | l50 | 49.9 | 1501 | 0 | 0 | 0 | 115 / 153 / 164 | 28.5% / 38.6% |
| | l100 | 98.8 | 3002 | 0 | 0 | 0 | 370 / 951 / 1043 | 57.4% / 83.2% |
| | l200 | 119.1 | 3922 | 0 | 0 | **2079** | 3317 / 4380 / **5001** | 70.7% / 88.5% |
| 改后 `1535a09` 默认配置 | l50 | 50.0 | 29 | 1472 | 0 | 0 | 2.7 / 5.8 / 85 | 1.5% / 9.6% |
| | l100 | 100.0 | 29 | 2971 | 0 | 0 | 1.9 / 4.5 / 21 | 1.8% / 8.6% |
| | l200 | 200.0 | 29 | 5971 | 0 | 0 | 1.6 / 3.8 / 7.7 | 2.2% / 8.8% |
| 隔离：`1535a09` 仅把 login-ip 调到 1e6（**仅用于观察 A4，非生产配置**） | l50 | 49.8 | 1501 | 0 | 0 | 0 | 121 / 162 / 183 | 30.0% / 41.4% |
| | l100 | 98.0 | 2280 | 720 | 0 | 0 | 174 / 723 / 869 | 48.4% / 55.6% |
| | l200 | 191.1 | 2008 | 3993 | 0 | 0 | 20 / 818 / 1495 | 45.2% / 55.8% |

结论：
- **默认配置**：单 IP 每档成功 29 次（20/分钟、突发 20，30 s 内补约 10 个），其余立即 429（p99 ≤ 85 ms），CPU 几乎为 0。这是 A2 的按 IP 限流按设计生效，**不是容量数据**。
- **隔离运行（只看 A4）**：429 只能来自 BCrypt 线程池（login-ip 已调高；每个账号只登录一次，login-user 不会触发）——这一归因是排除法，池拒绝没有单独指标。与改前相比：
  - 200 rps 下改前 k6 丢弃 2079 次迭代、p99 5.0 s、CPU 峰值 88.5%；改后无丢弃、无 5xx，成功约 64/s，其余快速 429，p99 1.5 s，CPU 峰值 55.8%。过载时延迟和 CPU 有上界，达到 A4 的目的。
  - **代价**：默认池大小 = 核数/2 = 8 线程、队列 32，成功吞吐上限约 64–75/s。改前在 100 rps 时全部成功（p99 1.04 s），改后 100 rps 有 24% 被 429。是否调整 `content.auth.bcrypt-threads` 默认值见计划 A4 的遗留项（待决定）。

# M0–M3 验收测试矩阵

所有用例为待实现契约。涉及事务、Redis 或 MQ 的用例使用实际组件。并发测试用屏障和故障钩子控制顺序，避免依赖 sleep。记录请求、事件、任务、token、游标与数据库结果。端到端核验使用预定的候选集合和权威 SQL 顺序。

| 用例 | 阶段 | 场景与注入点 | 通过标准 |
| --- | --- | --- | --- |
| M00 | M0 | Windows 上启动 Compose、空库迁移、重启并再次迁移 | 健康检查通过，迁移可重复执行，约束生效。 |
| M01 | M1 | 重放发布请求；在 Post 更新后和提交前注入失败 | 只发布一次，仅一个 Outbox 事件；回滚时两者均不存在。 |
| M02 | M1 | Broker ACK 后、标 SENT 前终止 Relay | 恢复后重投同一事件 ID；Relay 最终 SENT。 |
| T01 | M2 | 同毫秒 ID 9、10、11，limit=1 | 11、10、9，各一次，最终 EXHAUSTED。 |
| T02 | M2 | 同毫秒 501 条，低页大小与扫描预算 | 与 SQL 排序逐项相同，游标前进，覆盖全部。 |
| T03 | M2 | 前 100 个候选下架，预算小于 100 | 出现空页 UNKNOWN；逐页边界严格前进，能读到后续可见帖并终止。 |
| T04 | M1/M3 | 两种锁竞争顺序发布与双向模式切换，延迟旧事件 | 每帖只取得一种模式归属，Worker 与 Reader 一致；旧事件不改判。 |
| T05 | M3 | 双向切换保留历史；PUSH→PULL 后清空 Redis | 权威读取覆盖原区间；恢复结果与权威数据一致，记录恢复时间。 |
| T06 | M3 | Inbox+Task 提交前、提交后 ACK 前分别崩溃 | 回滚不留半记录；重投只保留一项任务，最终完成。 |
| T07 | M3 | Redis 批次部分失败；另在全部成功后进度提交前终止 | 部分失败不推进；重跑不重复展示，进度收敛。 |
| T08 | M3 | A 租约过期，B 接管后 A 再尝试 ZADD 和推进进度 | A 无法推进或完结任务，迟到写不改变可见集合或顺序。 |
| T09 | M3 | 暂停旧代次分发，取关、重关注，再放行；覆盖 N 和时间窗边缘 | 取关期间不可见，旧越界帖仍不可见；新历史集合和新帖各出现一次。 |
| T13 | M2 | Push 与 Pull 返回重叠帖子，预取多于当前页，页尾有剩余 | 固定集合与 SQL 顺序完全一致，未消费预取项在后续页出现。 |
| T14 | M2 | 翻页后插入边界以上和以下的迟到帖；另让某路取队首超时 | 以上迟到项只在刷新后的链路有机会出现；以下项可按序进入。超时不冒充耗尽。 |
| T15 | M2 | 连续空 UNKNOWN、令牌篡改、换用户与关注版本变化 | 空页必推进并终止；非法令牌拒绝，关注版本变化要求刷新。 |
| T16 | M3 | 重建期间保持权威读取，覆盖验证前模拟重启 | 没有就绪证明时不切回 Redis；最终按一致覆盖切换或要求刷新。 |
| T17 | M3 | 关注先发布后及发布先关注后，重复关注请求 | 帖子按锁定顺序归入当前代次历史或新帖，重复关注不生成新代次。 |
| T18 | M3 | 多次快速双向迁移及重复/乱序事件，交叉下架 | 仍有效的历史区间都被覆盖，已下架项不可见。 |

T10 拆为 T10a–c 随 M4–M6 验收。T11 的媒体旧版本重放随 M6 验收。T12 的完整强制终止与正常停机矩阵在 M7 验收，M1/M3 已使用强制终止验证相关恢复。详见 ADR-004。

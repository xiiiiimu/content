## 范围与依赖

实现请求内多来源降序归并内核、有界候选扫描、按帖子去重、权威校验接口及结构化续读状态。使用 Story 1 Redis 适配器；增加有界 SQL 测试来源，与真实 MySQL 权威排序核对。用夹具提供可见性与关注代次判定，不将夹具宣称为生产关注或分发实现。生产来源覆盖证明、用户关注读取、权威状态查询的具体接线必须在上线前完成。

本 Story 不实现 HTTP、签名/序列化游标、关注生命周期、MQ 分发、Redis 重建或完整 M2 验收。内部 continuation 不能暴露为可信客户端令牌。T15 本轮仅覆盖空 UNKNOWN 的前进，篡改/换用户/CURSOR_STALE 签名验证留后续 Story。无新增表的预期；若实现需要迁移须另行说明，不改已执行迁移。

## 比较和边界

元组 K=(published_at_ms,post_id)，按两个整数先时间再 ID 比较，输出 DESC。为避免“之前/之后”歧义，下文只使用 K>B 和 K<B。snapshotTime 在同一翻页链固定。初始只有 time<=snapshotTime；任何后续来源读同时满足快照与所有有效排他边界。

| 状态 | 定义与推进 |
| --- | --- |
| globalBoundary G | 整条翻页链最后实际返回的元组；首屏 null。只在可见去重项加入 items 后更新；空页继承原 G，绝不按预取或过滤项更新。 |
| consumedBoundary C | 最后完成全局处理的唯一元组，包括过滤项。一次处理必须完成所有相等队首的去重和权威判定；失败不提交这一元组的位置。C 只严格变小，未处理候选不得使它前进。 |
| sourcePositions P[s] | 本请求内该来源真正消费的位置，初始为输入 G、C 的较小非空值；null 不参与最小值。消费相等队首时只推进包含该元组的来源，不按批次末尾推进。 |
| pendingCandidates | 请求内、每来源有界的有序预取缓冲；取数据不推进 G/C/P。用于确认队首，不能将适配器 lastReadBoundary 直接当作消费位置。 |

实际来源读的排他上界取 G、C、P[s] 中较小非空值，并施加 snapshotTime。源内未消费缓冲仍有效时不重复拉取该段。SQL 使用 `published_at_ms < :ts OR (published_at_ms = :ts AND id < :id)`、二元组 DESC 和固定 LIMIT；Redis 使用 ADR-001 BYLEX REV，OFFSET 固定为 0。

跨请求只保存 snapshotTime、G、C 及未来协议需要的上下文，不携带按作者增长的 P 数组、pending 或累计 ID 集。翻页丢弃缓冲，下一请求各 P 从共享边界重建，未消费预取安全重读。已消费过滤项不重扫；预取但未消费项不会因批次末尾边界而丢失。

## 归并与原子消费

1. 每个逻辑来源必须成功确认有序队首或本范围正常耗尽，再选择所有队首中的最大 K。来源排序失序、同帖不同不可变元组、格式损坏均是契约错误，不能静默重排、过滤成空或继续推进。
2. 找齐所有相等队首，一次消费为一个全局候选。先完成权威存在性、发布/下架状态、当前关注代次等判定，再提交相应 P 和 C；通过才追加 items 并更新 G。等值重复不重复展示，scanned 只加 1。源内同元组重复也需合并；来源接口必须有稳定的严格排他续读能力。
3. 任一路未知队首时，不能越过该未知区间消费其他来源候选。补充队首后再选最大；批量权威预校验可以缓存，但不提交未逐项处理的位置。
4. 可见性过滤后继续归并补页，直到页满、预算停止或所有来源耗尽。固定数据集下输出与权威排序逐项一致。来源定义须证明所需候选覆盖；Redis 空键本身不能证明整个 Feed 的覆盖完整。

## 预算和三态

采用初值：最多 8 个逻辑来源，pageSize 1..100，每源批次 32（始终不超过适配器 200 上限），每请求最多消费 256 个唯一元组、最多 64 次来源读取，每次来源超时 2 秒。总预取缓冲最多 8×32 项。每源操作串行或并发有上限，禁止按作者无限增加逻辑来源；大作者集合未来由单一 SQL 有序来源聚合。上述是归并层初值，不声称容量验证完成。

预算分开统计 scanned（完成处理的唯一元组）、fetched（含重复的实际拉取条目）和 sourceReads（含空读/失败调用）；返回 scanned 只表示本请求完成处理的候选。读次数与批次长度共同限制预取工作；权威查询也必须分批、有次数和超时上限，计入单独明确的校验预算，不能隐藏无界补查。拟定每请求最多 256 次唯一元组校验，批量不超过 32。

配置必须允许初始化所有来源并完成至少一个全局元组的读取和校验；来源数超限或预算不足在扫描前拒绝。时间耗尽不等同于来源超时：预算停止可产生 UNKNOWN，但任意正常空 UNKNOWN 必须有本请求新消费的 C。初始化/校验超时、来源失败、或无进展且无法确认耗尽/后续候选时返回可重试错误，调用者保留输入 continuation；不返回无法前进的空 UNKNOWN。

| pageState | 精确定义 |
| --- | --- |
| HAS_MORE | 完成本页后，已成功取得至少一个尚未消费、满足安全上界的候选（可尚未通过可见性判定）；不是承诺下一页一定有可见项。返回非空 continuation，保留 G/C；已知后续候选不因预算结束而降为 UNKNOWN。 |
| UNKNOWN | 没有已知剩余候选，预算已结束，且尚有来源未确认耗尽。返回非空 continuation。items 为空时 scanned>=1 且 C 严格小于输入有效边界（首屏从 null 取得首个 C）。 |
| EXHAUSTED | 本次所有覆盖所需范围的逻辑来源均正常确认耗尽且没有 pending；next continuation 为 null。仅是本次快照/边界/来源集合下的结论，不保证未来不再有迟到写入。 |

页满时进行有界队首确认以区分 HAS_MORE/EXHAUSTED；预算不足确认且无已知候选时为 UNKNOWN。确认操作不得消费下一页候选。来源读取超时、Redis 不可信、SQL 失败始终错误返回，不允许标记 exhausted，也不允许用预算 UNKNOWN 掩盖故障。允许未来以同一安全边界切换完整权威来源，但本轮不实现未经覆盖证明的降级。

## L1 与前进性

每个新请求重新读取共享安全边界以下的来源，不持久化跨请求 exhausted 标志。迟到 K 大于或等于当前安全边界的候选不得倒插本链，留待刷新首页；K 小于边界且 time<=snapshotTime 的迟到项可以按序进入。不会为迟到项回退 G/C；不声称对变化集合提供固定快照完整性。L1 对固定集合保证无重复、无遗漏、严格有序遍历。

空页推进示例：G=null，前 100 个元组均被过滤，扫描预算 16；各空 UNKNOWN 消费至新的 C，下一页严格小于 C，最终读到可见项或所有来源耗尽。不得让 globalBoundary=null 导致每次从头扫描。

## 实现边界与实际证据

- `FeedMerger` 为无 Spring 接线的内核，`RedisCandidateSource` 组合已有 Redis 适配器；SQL 来源及权威可见性读取位于 `FeedMergeIT` 夹具。没有新增 SQL 迁移、HTTP、身份、签名或生产关注/分发实现。
- 调用者提供受控的有限线程池、有限 I/O 超时与绑定读者上下文的权威校验。内核逐次等待来源/校验至多 2 秒；超时取消 Future，迟到任务不能修改请求内消费状态。取消不保证外部 JDBC/网络操作物理终止，连接超时及资源生命周期仍由调用者负责；拒绝执行也返回可重试失败。没有承诺整个请求仅耗时 2 秒，工作总量由读取/消费/校验次数分别限制。
- 当前权威校验逐个执行（批大小 1），最多 256 次，单次最多 2 秒。可见项必须返回完全一致的 canonical 元组；缺失帖子仅允许 `(null,false)`。隐藏/关系代次不符仍需核对已有帖子的 canonical 元组。实现对本请求预取的同 ID 不同元组直接拒绝；跨请求不保留 ID 集，依靠不可变发布契约及每次权威核对防止错误重现，不能以恒真校验器作为生产接线。
- 实际边界始终取共享 G/C 与来源消费位置的较小值，来源返回超快照、非排他、乱序、超批次或空且未确认耗尽的结果都失败。来源耗尽仅限本次读取范围，Redis 空范围不提供覆盖/恢复就绪证明。

## PR #4 审查补充：预算及夹具证据的精确范围

- 默认最多 64 次来源回调、每批最多 32 项，因此接受的拉取项最多 2048（含跨来源重复）；当前缓冲最多 8×32=256 项，请求内身份核对表最多 2048 项；最多消费/权威检查 256 个唯一元组，返回最多 100 项。页满后的队首确认也计入来源读取次数；失败没有成功页，不能使用部分结果的边界。
- 这些是内核层工作量约束，不是数据库物理扫描行数、任意回调内部 SQL 次数或总请求时延的保证。内置 Redis 适配器使用有界 ZRANGE 和 ZCARD/ZCOUNT 元数据检查，不读取全键成员；SQL 测试来源虽有 LIMIT，MySQL 为过滤/排序实际检查多少行仍取决于执行计划。生产适配器必须另外约束内部查询、超时、线程/连接队列并验收执行计划；不能以 Future.cancel 已调用当作底层 I/O 已终止。
- 单元测试的内存来源会对固定小夹具全量过滤/排序；集成测试的全量 SQL 查询只用于 501 项等固定夹具的排序 oracle。它们不是生产候选来源，也不提供生产容量或无全表扫描的证据。
- 真实 SQL 权威夹具实际只核对帖子 canonical 元组及 status=PUBLISHED，没有读取 follows、follow_history 或 follow_graph_version。单元测试中“关注代次拒绝”用例仅注入一个 false 判定来验证过滤后的归并行为，不证明真实关注/重关注/回填权限协议已实现。ADR-003 的完整读取谓词、图版本和 M3 生命周期尚待后续 Story。
- EXHAUSTED 是调用者已证明覆盖的来源集合在当前范围正常耗尽；当前夹具的完整覆盖由种入集合证明。任意生产 Redis 空键、单独的 PULL 来源或当前作者模式都不能替代 PUSH 历史、旧 PULL 历史及缺失缓存的覆盖证明。

## Services

| Service | Role |
|---|---|
| Java `content` | Comments, assistant_tasks, search execution, feedback subscribe/resolve, giveaways, entitlements, notifications |
| Python `assistant-python` | Intent/parameter parsing only (`POST /v1/parse`). No DB. Auth: `X-Content-Internal-Token` |

When `content.assistant.python-url` is empty, Java uses `StubAssistantParser` (deterministic stand-in). With the URL set, Java calls the Python FastAPI service. Python picks its parser from `CONTENT_ASSISTANT_PARSER_MODE`: `rules`, `llm`, or `llm_with_fallback` (the default: an LLM with the rules parser as fallback). The provider is configurable with `CONTENT_ASSISTANT_LLM_PROVIDER` (`openai_compatible` or `anthropic`, model and base URL configurable too); the default is DeepSeek `deepseek-flash`. See `assistant-python/eval/README.md`. The contract is unchanged, apart from the additive `source`/`fallbackReason` fields. Java's call timeout `content.assistant.parse-timeout` (default 30 s) must stay above Python's LLM worst case (about 21 s).

`AssistantTaskCreated` is emitted to Outbox, relayed over RocketMQ, accepted in Inbox (`ASSISTANT_ACCEPTED`), then `AssistantService.tick()` is kicked (and also polled by `mediaRunner`).

## Eligibility tools and assistant command validation

Enabled tools: `LIKE`, `COMMENT`, `FAVORITE`, `FOLLOW`, and `PURCHASE`. `PURCHASE` has been enabled since `c79bf3b`: `EligibilityRegistry` turns it on when the order source (`SaleMapper`) is present, and the parser puts "购买/买过/下单" into the rule tree as an ordinary condition. Only `PURCHASE` takes a parameter, `params.postId`; any other key in the rule tree is rejected.

Conditions the platform cannot evaluate or grant must be reported by the parser in `unsupportedTools`, never dropped. Examples: 转发、分享、评论字数、关注时长、@好友、打赏、等级、弹幕、下载记录、否定条件、转售授权、其他帖子的奖品、作者本人参与、同一人多次参与. When the list is non-empty, Java rejects the whole command (task `REJECTED`, with one reply giving the reason).

Hardening A11: whatever the parser returns, Java checks the command independently before any side effect.
- **Subscribe**:
  - the target must be a feedback comment (it has a material version) on this post, and not written by the assistant; otherwise `CLARIFY`;
  - only `action=SUBSCRIBE|CANCEL` with `target=SELF` is accepted; `OTHERS`/`ALL` are rejected;
  - `CANCEL` cancels an active subscription, or does nothing if there is none; it is never executed as a subscription.
- **Giveaway**, checked from the database:
  - the actor must be the post's author;
  - the rule tree must use only enabled tools and known keys, with a valid `k`;
  - the reward must be a READY version of this post; unknown hints are rejected, not defaulted;
  - a `COMMERCIAL` reward requires `license_commercial` on the material;
  - 1–100 winners; the deadline must be in the future; `windowStartMs` must be earlier than the deadline.
  - At sealing, the author and the assistant are never candidates, and each account enters at most once.
- The parser `context` carries `parentKind` (feedback/ordinary/assistant/null), `parentIsFeedback`, `nowMs`, `timezone`, `postLicenseCommercial` and `enabledTools`.

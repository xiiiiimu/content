# V1.1 Material Assistant

Stacked on material posts (merged to `main` via PR #13). Keep open until demo + CI on `main` base are green.

## Known limits (from #13 delivery)

- FFmpeg timeout tests cover the **Java `docker` CLI subprocess** (`destroyForcibly`); **actual container cleanup on timeout remains unverified**.

## Services

| Service | Role |
|---|---|
| Java `content` | Comments, assistant_tasks, search execution, feedback subscribe/resolve, giveaways, entitlements, notifications |
| Python `assistant-python` | Intent/parameter parsing only (`POST /v1/parse`). No DB. Auth: `X-Content-Internal-Token` |

When `content.assistant.python-url` is empty, Java uses `StubAssistantParser` (deterministic stand-in). With the URL set, Java calls the Python FastAPI service (also deterministic rules — not an LLM).

`AssistantTaskCreated` is emitted to Outbox, relayed over RocketMQ, accepted in Inbox (`ASSISTANT_ACCEPTED`), then `AssistantService.tick()` is kicked (and also polled by `mediaRunner`).

## Key APIs

- Comment with `@助手` / `@assistant` → normal comment + `assistant_tasks` + `AssistantTaskCreated` outbox
- `GET /api/posts/{post}/comments` — thread (assistant replies visible here)
- `GET /api/assistant/tasks/{id}`
- `POST/DELETE /api/materials/{post}/feedback/{comment}/subscribe`
- `POST /api/materials/{post}/feedback/{comment}/resolve` body `{versionId, offsetMs?}`
- `POST/DELETE /api/posts/{post}/favorite`
- `GET /api/posts/{post}/giveaways`, `GET /api/giveaways/{id}`, `GET /api/posts/{post}/entitlement`
- `GET /api/notifications`, `GET /api/notifications/{id}/target`
